# 协作指南（Collaboration Guide）

[English](./COLLAB.md)

Excali Local 1.8.0 的实时协作：**无宿主、端到端加密的房间，跑在你自行部署的中继（relay）之上**。Excali Local 项目本身不运营任何后端——扩展项目没有任何服务器，中继是一个小巧的 partyserver 参考实现（Cloudflare Durable Objects），只负责在你的团队浏览器之间转发密文。

决策记录：[ADR 0003 — 自带中继的实时协作](adr/0003-byo-relay-realtime-collab.md)。

---

## 概览

- **每个扩展一个中继。** 每个团队部署一次中继（一个小型 partyserver 项目，约 150 行）。扩展**永久地、同一时刻只连接一个中继**；接受新服务器邀请即替换已存配置，不存在多中继列表。
- **无宿主房间。** 协作会话是本地优先画布之上的一层临时叠加。没有创建者权威、没有房主、没有房间注册表：一个房间就是它的邀请载荷加上中继的内存快照。保存仍然是显式的（每个成员"保存到我的图库"）。
- **默认端到端加密。** 团队房间对**组织（org）**端到端加密；私有房间**按房间**端到端加密。中继只存储和转发**密文 + 成员签名**——它不持有任何组织的解密密钥。
- **包含文件同步。** 图片/文件引用走同一条线路协议，按需分块拉取，blob 加密传输（单文件 20MB 上限，见[已知限制](KNOWN_LIMITATIONS.zh-CN.md)）。
- **零后端。** 中继是唯一的活动部件，而且它是你的。

## 部署一个中继

中继是一个 [partyserver](https://github.com/cloudflare/partykit/tree/main/packages/partyserver)
项目（Cloudflare Workers + Durable Objects）。用 wrangler 部署到**你自己的
Cloudflare 账号**——不需要 PartyKit 云、无需额外登录；或用 `wrangler dev` 本地跑
（见[本地开发循环](#本地开发循环)）。

> **不用 Cloudflare？** Durable Objects 运行时可以自托管：
> [celld](https://github.com/denoland/celld) 内嵌 V8、直接执行 wrangler 打包产物
> （Workers + Durable Objects）跑在你自己的机器上——每个 DO 由 SQLite 支撑、
> 复制到你自有的 bucket（S3/GCS/Azure），无控制面。这是本中继可行的非
> Cloudflare 路径，无需重写 WS 服务器。
>
> **实证状态（2026-08 测过）：对本中继当前被阻塞。** celld v0.3.0 内嵌 V8 拒绝
> `crypto.subtle.importKey("raw", …, { name: "Ed25519" })`（"unsupported key
> import"），导致中继的 org 签名准入对每个 hello 都验签失败——所有连接被拒。
> 其余链路（`celld deploy`、DO cells、hibernatable WebSocket、vars）均正常；
> 待 celld upstream 支持 Ed25519 后重新评估。

下面所有 wrangler 命令都在 **`packages/collab-relay/`** 目录执行（`wrangler.jsonc`
在那里）；`pnpm relay:keygen` 是**仓库根目录**脚本：

```bash
cd packages/collab-relay          # ← 所有 wrangler 命令在这里
cd <仓库根> && pnpm relay:keygen …   # ← keygen 在这里
```

### 1. 前置条件

```bash
cd packages/collab-relay
pnpm install          # 工作区安装（中继包是工作区成员）
npx wrangler login    # Cloudflare 账号（或 export CLOUDFLARE_ACCOUNT_ID + CLOUDFLARE_API_TOKEN）
```

### 2. 先部署，拿到你的中继 URL

服务器邀请内嵌中继 URL，所以**先部署再 keygen**：

```bash
cd packages/collab-relay
npx wrangler deploy   # → 打印 https://excali-local-collab-relay.<账号>.workers.dev
```

worker 名称来自 `packages/collab-relay/wrangler.jsonc`。自定义域名：Cloudflare 控制台或 `wrangler.jsonc` 的 `routing` 规则——如果用了自定义域名，重新部署并用那个 URL 生成邀请。

> **`*.workers.dev` 在中国大陆被阻断**（DNS 污染 + SNI/TLS 丢包——GreatFire 实测 147/149
> 个子域被封）。症状：TCP 能连、TLS 永不完成，扩展报 "WebSocket is closed before the
> connection is established"。如果你的用户要在中国大陆访问中继，**必须绑定自定义域名**
>（域名 DNS 托管到 Cloudflare → Workers → Settings → Domains & Routes → Custom Domains →
> 添加），并用该 URL 重新生成邀请。普通 Cloudflare 任播 + 自定义域名在大陆一般可用，
> `*.workers.dev` 不行。

### 3. 生成密钥与服务器邀请（仓库根目录）

```bash
cd <仓库根>
pnpm relay:keygen --org acme --relay https://excali-local-collab-relay.<账号>.workers.dev
```

打印 (a) 供下方环境变量使用的 `ORG_PUBKEYS` 条目，以及 (b) 面向你的组织标签和
中继 URL 的、可直接粘贴的**服务器邀请**。输出请妥善保密——`sk`/`ck` 仅存在于
客户端配置（见下）。

```text
server invite = excali-collab:v1:srv:<b64url(JSON { relay, org, sk, ck })>
  relay   https:/wss: 你的部署 URL（http:/ws: 仅限本机回环 IP，用于开发）
  org     你的组织标签——信任确认时显示在 URL 旁边
  sk      组织 Ed25519 种子，32 字节 b64url——签署 hello（准入证明）
  ck      组织内容密钥，32 字节 b64url——加密团队房间内容
```

`sk` 和 `ck` **仅存在于客户端配置**：它们随服务器邀请分发、存放在扩展的本地配置里，**绝不发送给中继**。中继环境里只有公开验证密钥。

### 4. 设置环境变量（中继目录）

`ORG_PUBKEYS` —— JSON 数组 `{ org, pubkeys[] }`，其中每个 pubkey 是组织的 32 字节 Ed25519 公钥（b64url，43 字符）：

```jsonc
// [{"org":"acme","pubkeys":["x57…","yQ2…"]}]
[
  { "org": "acme", "pubkeys": ["<pk b64url>"] }
]
```

二选一让它生效（都在 `packages/collab-relay` 目录执行）：

```bash
# (a) 写进 wrangler.jsonc 的 vars —— 最简单；ORG_PUBKEYS 是公开验证材料，
#     提交进配置没有安全问题：
#     "vars": { "ORG_PUBKEYS": "[...]" }
#
# (b) wrangler secret put —— 值走 stdin（不用和 shell 引号搏斗）：
echo '[{"org":"acme","pubkeys":["x57…"]}]' | npx wrangler secret put ORG_PUBKEYS

# 然后重新部署让环境变量生效：
npx wrangler deploy
```

- **每个组织的数组即轮换宽限期**：在重新签发窗口期内同时保留旧、新密钥，之后删掉旧的并重新部署（见[密钥轮换](#密钥轮换)）。
- 一个中继可托管多个组织——每个组织一条。**多 org 是计划中的设计；v1 实现实际为
  单 org**——开发循环只注册一个组织（`local`），每个客户端也只持有一份服务器配置
  （一个 org 标签）。数组结构是向前兼容的：以后新增组织只是改配置，不是破坏性变更。
  多 org 注册针对的是*准入密钥*，不是房间租户——见[安全模型](#安全模型)。
- `ORG_PUBKEYS` 为空/格式错误 ⇒ **所有准入全部失败**（故障时默认关闭）。
- 旧版：1.8 之前的中继使用 `ORG_SECRETS`（org → secret 对象）。v2 中继只要存在 `ORG_PUBKEYS` 就完全禁用旧路径。

### 5. 配置扩展

## 生成与分享邀请

### 服务器邀请（准入）

每个组织一份，部署时生成（见上）。包含中继地址、组织标签、组织签名种子和组织内容密钥。分发给组织成员，每个成员在"选项 → 协作"里粘贴一次。

### 房间邀请（成员资格）

```text
room invite = excali-collab:v1:room:<b64url(JSON { shareId, tier, roomSecret?, fp? })>
  shareId     128 位随机能力令牌（约 22 字符）——房间 ID 本身就是权限
  tier        "team"（默认）或 "private"
  roomSecret  仅私有房间有——按房间的 E2E 密钥
  fp          可选服务器指纹（短哈希，仅警告——绝不作路由输入）
```

- **房间邀请绝不携带服务器地址**——单中继不变式让路由没有歧义。
- 分享方式是**句子 + 代码**：邀请以一句短句连同行内令牌一起复制（聊天软件里不会丢）；分享步骤上另有"仅代码"按钮。粘贴框两种形式都接受——解析器会提取令牌。
- 如果将来邀请以 URL 形式分享（web 包装），载荷放进 **`#` 片段**，这样它永远不会到达任何服务器，包括中继。
- v1 中房间层级在创建时不可变——改层级就是新建房间。

在协作编辑器中粘贴房间邀请即可加入房间；在那里创建房间即可铸造一份。

**编辑器一键建房。** 本地编辑器的右上角 **Collab ▾** 菜单可以直接用当前画布创建房间：「以当前画布创建房间」会把当前场景暂存为房间的种子（空房间/休眠房间直接采纳——先到先得），并直接跳入 `#room/<shareId>`。房间以团队级别创建，自动命名为「未命名房间」——可在会话栏中重命名。第二项「打开协作页面」则进入协作首页（加入 / 我的房间 / 服务器配置）。Quick 编辑器工具栏保持不变。

## 密钥轮换

轮换 = **用新的 `ORG_PUBKEYS` 数组重新部署 + 分发新的服务器邀请**。中继零停机。

- **宽限期：** `pubkeys` 是数组——在重新签发窗口期内同时保留旧、新密钥，之后删掉旧的并重新部署，旧邀请即失效。在此之前，持旧密钥的成员仍可准入。
- **邀请泄露 = `sk` 和 `ck` 一起泄露** → 两者一起轮换。仅轮换 `sk` 是常规卫生操作：`ck` 不动意味着团队房间快照仍可解密——无需重置房间。
- **轮换 `ck` 的副作用：** 中继上存储的团队房间密文对所有人变得不可解密（加入时 GCM 认证失败）→ 团队房间重置；成员从本地图库重新播种——成本很低，因为房间本来就是临时叠加层。私有房间不受影响（每房间独立密钥）。

**什么会坏，以及恢复路径：**

| 信号 | 何时 | 文案族 | 恢复 |
|---|---|---|---|
| hello 时 `ADMISSION_INVALID`（致命，连接关闭） | `sk` 过期——没有注册的 `pk` 能验证你的签名 | `stale.admit`："服务器拒绝了此成员密钥 / 邀请可能已过期。" | 在"选项 → 协作"重新粘贴服务器邀请 |
| 首个快照/场景 GCM 认证失败 | `sk` 仍有效但 `ck` 已轮换 | `stale.gcm`："房间密钥不匹配 / 此房间可能已被重建。" | 让房主重新复制完整房间邀请（若组织密钥轮换则粘贴新的服务器邀请） |

会话中途轮换呈现同样的文案族：连接变红"rejected"，重试停止，横幅提供**保存到图库 / 离开**。

## 本地开发循环

```bash
pnpm relay:dev        # 一条命令：seed → .dev.vars → 打印邀请 → wrangler dev
pnpm relay:dev:https  # 可选 TLS 对等模式（mkcert）
```

`pnpm relay:dev`：

1. **幂等 seed** — 在仓库根目录生成一次 `.dev-keys.json`（组织 Ed25519 种子 + 内容密钥）；再次运行直接复用（重新 seed **不得**轮换密钥——你的开发邀请要跨天持续有效）。
2. 写入 `packages/collab-relay/.dev.vars`（已 gitignore）：`ORG_PUBKEYS`（v2）+ 兼容用的旧版 `ORG_SECRETS`。wrangler dev 会自动加载它。
3. 打印**面向 `http://127.0.0.1:1999` 的可直接粘贴服务器邀请**——回环例外：`http:/ws:` 只接受 IP 字面量 `127.0.0.1` / `[::1]`；远程流量保持仅 TLS。
4. 针对 `packages/collab-relay` 运行 `wrangler dev`（端口 1999）。

从全新克隆到跑通协作：

```bash
pnpm install
pnpm relay:dev                    # 终端 1 —— 记下打印的邀请
pnpm page:dev                     # 终端 2 和 3 —— 两个编辑器窗口
# 在两个窗口的"选项 → 协作"里粘贴邀请
# 在窗口 A 创建房间 → 把房间邀请粘贴进窗口 B → 开画
```

- **两个窗口测管道，两个 profile 测加密。** 成员密钥每安装实例铸造一次，所以同一 profile 的两个窗口共享一个成员密钥——测广播/名单没问题，但诚实的成员签名验证测试需要两个 profile（或 Chrome + Firefox）。
- **清空状态模拟。** `wrangler dev` 默认持久化房间状态（`packages/collab-relay/.wrangler/state`——已 gitignore），与生产环境的驱逐语义相反。`rm -rf packages/collab-relay/.wrangler/state` 可模拟房间死亡，走一遍"死房间重新播种"的提示路径。
- **`--https`（mkcert）：** `pnpm relay:dev:https` 生成本地 CA 证书（`.dev-cert.pem` / `.dev-key.pem`）并以 wrangler 的 `--local-protocol https` 模式运行——得到真实的 `https://localhost:1999`，用于一次性 TLS 对等检查（重连/TLS 失败 UX、严格 https 解析路径）。

**本地开发无法模拟的**（workerd 官方文档）：dev 服务器从不休眠，驱逐时机不可观测。休眠路径要做一次已部署中继的冒烟测试：成员保持连接、空闲 ≥10 秒、重连，确认快照仍然存活。

## 房间生命周期

- **播种。** 空房间/死房间的第一个成员会被提示从图库加载场景或从空白开始。**先到者胜**——它成为房间快照；并发的第二个 seed 会收到非致命的 `SEED_REJECTED`，改为直接加入实时会话（中继的单个 DO 实例串行化竞争；无需仲裁）。
- **共享房间名（ADR 0004）。** 每个房间有**一个广播名称**——和场景一样属于房间内容。它存在 `room.storage` 里、位于快照旁（生命周期相同，随房间一起消亡），按中继到达次序后写覆盖（LWW），**任何成员**都可改名（房间没有房主）。`welcome` 携带房间名；`room-name` 广播改名，作者通过名单反查。本地 `rooms` 条目的 label 只是镜像；真正命名的 label 会在房间无名时被*推送*为房间名（首次命名 / 死房复活）。
- **成员显示名（ADR 0006）。** 成员有一个**个人资料默认显示名**——在身份中铸造一次，在共享配置区（选项）里编辑、即时生效、始终非空、修剪后 ≤ 40 字符——外加一个可选的**按房间名字**：进入房间（加入*和*创建）时对默认名做一次性*复制*，之后成为独立值、再进入时复用。之后再改默认名也不会波及已进入的房间（复制语义）。改名走专用的 `member-name` 线路消息（镜像 `room-name`，ADR 0004）：客户端发送 `{name}`，中继修剪/校验（非空、≤ 40）、更新名单中*发送方*成员的记录，并广播 `{name, from}`（`from` 由中继在信封层盖章，发送者本人排除）。名字随连接一起消亡——不会写入 `room.storage`。接收方客户端即时更新名单和画布协作者徽章——无需重连、无 toast；`welcome.peers` 让后加入者看到当前的按房间名字。
- **房间探测（ADR 0004）。** 一个轻量级进房前查询（`room-probe`——无需准入、不进名单、无成员可见副作用）返回 `{roomName, snapshotAvailable, peerCount}`。加入页用它显示真实名字，并据此门控播种提示：只有当中继确实说空时，才显示"此房间是空的"。
- **快照和文件存放在 `room.storage`。** 它们能扛过 DO 休眠（约 10 秒静默——内存字段被丢弃但存储保留）和代码部署（socket 断开、存储保留）。它们**只随房间消亡**：空房间 + 约 70–140 秒后驱逐，全部删除。任何用户可见的东西都不会在服务器端累积。
- **重连重新同步。** 客户端带封顶退避重连、重发 `hello`，拿到新的 `welcome` + 快照——快照就是重新同步点，断线期间丢失的广播都会被找回（然后走下面的合并）。
- **隐私层级。** 团队房间（默认）对*组织*端到端加密（`ck` 来自服务器邀请）；私有房间*按房间*端到端加密（`roomSecret` 只存在于邀请中）。两个层级的加密机制字节级一致——只有密钥来源不同。中继在**每个房间里都是内容盲的**：它只看到路由元数据、消息大小和签名——永远看不到密钥，也看不到明文。`welcome` 的隐私标志让界面在无密钥时也能显示"此房间已端到端加密"——这只是 UX 提示，绝不是安全机制。

## 客户端语义

- **再进入规则（ADR 0005）。** 加入时按客户端是否与该房间同步过（缓存 `base` 非空）区分：**从未同步** → **房间权威**——快照原样应用，任何暂存 seed 被静默丢弃（不合并、不回传）；**同步过** → 走下面的三方合并不变。房间死亡永不浮现（054 Q7），所以死房重种后的回归与活房重连行为完全一致。
- **重进与恢复时的三方合并。** 重新进入一个*同步过*的房间（或会话中途链路恢复）时，客户端合并 base（上次同步的场景）/ ours（本地编辑）/ theirs（快照）。单侧改动干净合并；无法解决的冲突——同一元素两侧都改过（改-改、改-删、删-改）——按**在线版本胜出**处理：本地改动被强制重置并给出琥珀色提示（"N 处本地编辑发生冲突——已保留在线版本"，附"显示"高亮）。没有离线编辑的纯缓存则直接被快照覆盖。合并结果**仅当与在线场景不同才回传**（本地新建存活时）——相同的结果对其他人毫无增量。
- **连接健康词汇。** 会话工具栏里一个圆点：**live**（绿色常亮——只有圆点）、**connecting**（蓝色脉冲，首次连接）、**reconnecting**（琥珀色脉冲——圆点 + 文字）、**rejected**（红色常亮——仅致命错误）。悬停提示 = 状态 + 一行详情。恢复后**静默回绿**。
- **会话中途服务器宕机。** 自动重连永不放弃；离线期间可继续自由编辑。T+60 秒横幅只升级文案（已等待时长 + 继续等待 / 保存并离开）。离线横幅承诺"编辑会保留，恢复后同步"，并附一行冲突预警。名单冻结变暗——悬停显示"presence frozen"，横幅点出人数（"掉线时有 N 位协作者在房间里"），冻结的名单永远不会被误读成"大家都走了"。成员离开仍是静默淡出。
- **服务器宕机时重进。** 10 秒超时 → 红色卡片"无法连接你的团队服务器"，带**重试 / 打开最后同步的副本 / 离开**。"我的房间"条目绝不会因宕机置灰。
- **降级但存活。** 默认静默；5 分钟内重连 ≥3 次 → 每会话一条琥珀色提示（"连接不稳定——编辑仍会同步"）。

## 安全模型

- **准入 = Ed25519 签名，而非密钥比对。** `hello` 携带对完整 hello 载荷（域名前缀、固定属性顺序）的组织签名，外加成员的公钥（每安装铸造一次）。中继针对该组织注册的每一个 `pk` 验证——所以它能*验证*准入，但**不能铸造邀请、不能冒充成员**（它从不持有 `sk`）。
- **org 是准入 + 加密标签，不是房间租户。** 任何被准入到中继的成员，只要拿到某房间
  的 shareId 就能连进去——hello 绑定的 org 只决定他能*解密*什么（团队房间：本 org 的
  `ck`；私有房间：房间自己的密钥）。房间从不绑定 org；组织之间的房间级隔离是将来
  的工作——v1 实际为单 org（见上文"设置环境变量"）。
- **逐消息 E2E。** 内容密钥 = `HKDF-SHA256(baseSecret, salt=shareId)`，其中 `baseSecret` 是 `ck`（团队）或 `roomSecret`（私有）；每条消息 AES-GCM-256、全新 96 位随机 nonce；AAD 绑定类型 + 房间（或文件 ID）；密文内部的单调 `seq` 防重放；每条消息独立可解密，重连不需要任何加密状态。
- **每条加密帧都有成员签名**（Ed25519，签 `(t, room, c, iv)`）。客户端验证收到的每一帧并把签名者与名单交叉核对；中继只在其存储/服务边界验证、全程不解密。失败静默丢弃——数据面自愈（全场景 LWW，下一帧胜出）。
- **中继能做什么、不能做什么。** 它能验证准入、转发流量、存储和服务密文——也能**丢弃或扣留**任何东西（活性 DoS，是已记录的限制）。它不能读取内容、无法被察觉地篡改、不能以成员身份伪造帧、不能跨房间走私内容。
- **成员密钥泄露：** 没有逐成员吊销（按设计无 PKI）。驱逐走组织级路径：轮换 `sk`+`ck`、重新签发邀请、受影响成员重装（新成员密钥）。旧密钥签署的已存内容仍可通过自包含的 `signer` 字段验证。
- **信任边界。** 中继运营者被信任不丢弃流量；服务器邀请泄露会暴露该组织的团队房间（私有房间安全——每房间独立密钥）。密钥和房间列表存放在扩展本地存储中，与你的所有绘图同级。
